# C. A. R. Hoare (gloss)

Prior-anchor: **C. A. R. Hoare** — 1980 Turing lecture.

> "There are two ways of constructing a software design: one way is to make it so simple that there are obviously no deficiencies, and the other way is to make it so complicated that there are no obvious deficiencies. The first method is far more difficult."

Elegance-as-correctness: simplicity is the precondition for _seeing_ that a design is right. The load-bearing half is "far more difficult" — the hard simple design is _the job_, not optional polish to defer. Deferring the real fix is choosing the complicated way.
