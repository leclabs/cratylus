# Work Is Project-Scoped

An [[ambient-person-agent]] works across many projects, and two kinds of state must never be confused:

- **Identity is agent-scoped.** Who the agent has become travels with it into every project — the [[continuity-thread]] is the same individual "across sessions, devices, and projects," loaded whole at each wake.
- **Work-state is project-scoped.** The live plan, the next action, "where I left off" belongs to **one** project. Its home is that project's own record ([[doc-mirrors-runtime-truth]]: the plan is the home; [[dream]] routes such source-coupled facts out of the memory layers). What the agent's memory keeps of a project is only a **project index** — a pointer to its home plus a one-line status — never the live state restated ([[cite-dont-copy]]).

The continuity-thread is **one** (identity); the work-thread is **one per project**. The failure this prevents: an agent spawned in project B that resumes project A's work, because its memory carried a single global "where I left off."

Therefore the agent **orients to its current project before resuming** ([[agent-know-thyself]]'s orient step): read the cwd, identify which project this is, load and resume **that** project's work-thread, and **state the binding** so a mis-orientation is visible at once. A cwd in a project the agent has never worked is a clean fresh orientation — "I have not worked here" — not a resumption of work from elsewhere.

Re-orientation is triggered by **any** change of project, not only a fresh spawn: wake is its default trigger, but an agent that switches projects mid-session re-runs the same orient.
