# meaning-roles: record checks seen red (0133's four fixes)

Scope: decision 0133's four fixes, bound to workflow/24, 25, 31, 32, 33, 36 and 38 (`design/examples/workflow/meaning-roles.md`) under the freeze's current version and 0130–0134. `record.test.ts` holds the cases and `fixture.ts` the helpers. The cases reuse the frozen freeze fixture (`../freeze/fixture.ts`): its renewal cut, Givens, routes, oracles and clause record. No product source, example, journal entry, frozen check or held-out file was changed.

## What the checks run

- **Delivered code.** These are the packaged `cratylus` and its omp extension, exactly as `../freeze/seen-red.md` describes them.
- **The record.** After every Given that changes the ledger, `design/ledger/` is committed (`record`). The branch's recorded tip and the working copy therefore hold the same ledger, and what is frozen reads the same from either. **0134 is not bound either way:** no case depends on whether the ledger is read from the tip or from where cratylus keeps it. Every branch has recorded commits, so no case touches what a branch that has recorded nothing reads. Only the examples, checks and the files they use differ between the tip and the working copy, and only where a case says so. Givens are committed with `-c core.hooksPath=/dev/null`; they set the scene and are not attempts.
- **The wiring the record must work under (stated here).** The CLI README says to wire `cratylus freeze-gate` "as the hook" but not where. The frozen fixture writes `.git/hooks/reference-transaction` and sets `core.hooksPath` to the relative `.git/hooks`. Git resolves a relative path from wherever the hook runs, and that wiring breaks in two places:
  - In a linked work tree the hook runs from the tree's top, where `.git` is a file.
  - On a push the hook runs in the git directory, where `.git/hooks` does not exist.

  Either way the hook never runs. These checks therefore keep the same hook file, which is git's default location `$(git rev-parse --git-common-dir)/hooks/reference-transaction`, and unset `core.hooksPath`. Every work tree of the repository and every push into it runs that hook. `MEANING_RECORD_WIRING=fixture` restores the frozen fixture's wiring, and exists only to see the work-tree cases fail.

- **Refused and admitted.** These follow `../freeze/seen-red.md`: the frozen oracles `refusedChange`, `refusedCommit`, `admittedCommit` and `allowedChange`. They add the following:
  - **Widening refused:** the verb exits non-zero, nothing is added to `design/ledger/`, the output names the frozen file (or its folder), and `workPackage frozen` still lists the file under `uses`.
  - **Define refused:** exit 1 with one line `concepts define: …` naming the concept (and, while the freeze reads, the architect and the cut). Nothing reaches `design/journal/` (watched).
  - **Journal entry change refused:** git fails, the branch and HEAD stay (for a rebase, only the branch), and the output names the entry's id.
  - **Push refused:** the push fails, the repository's branch stays, and the output names `renewal`, the architect and the path. An unread freeze's refusal need only refuse.
  - **Admitted:** git or the verb exits 0, and the change is recorded.
- **Stand-in.** `MEANING_RECORD_STAND_IN=refuse` puts a refusing record in front of the delivered command from the point a test arms it, after its Givens. That record refuses every prepared `freeze-gate` transaction, `concepts define|supersede|retire`, and `workPackage submit|update`, and passes everything else through. `MEANING_FREEZE_CLAUSES=<file>` is the frozen fixture's clause record.

```sh
cd packages/cli
pnpm exec vitest run test/meaning-roles/record --reporter=verbose
MEANING_FREEZE_CLAUSES=/tmp/rec-current.jsonl pnpm exec vitest run test/meaning-roles/record
MEANING_RECORD_WIRING=fixture MEANING_FREEZE_CLAUSES=/tmp/rec-wiring.jsonl pnpm exec vitest run test/meaning-roles/record -t "fix 4"
MEANING_RECORD_STAND_IN=refuse MEANING_FREEZE_CLAUSES=/tmp/rec-refuse.jsonl pnpm exec vitest run test/meaning-roles/record
```

  - Every route admits a rewritten or deleted journal entry, the architect's and the lead's alike.
  - A push is admitted: the hook runs in the git directory, so the gate finds no ledger and passes it. The combined linked-tree case (fix 1 + 4) also fails, because the gate reads the linked tree's working copy.
- **The 10 refusals that hold against the delivered work** are the linked-tree cases for the example and for the unread freeze. Under the stated wiring the delivered gate runs in a linked tree, and since the ledger there is recorded, it reads the same freeze as everywhere else and refuses. Under the frozen fixture's wiring the hook never runs in a linked tree or on a push, and all 21 refusal clauses of fix 4 fail. These cases bind the work tree under any wiring the record states. They pass against the current runtime only once the wiring is the one stated above.
- **The 2 admissions that fail against the delivered work** fail because of refusals it admitted earlier in the same test: the lead's admitted `fines` leaves the architect's `fines` "already" defined, and admitted deletions remove entries the final check expects. Against a record that refuses every change, all 25 admissions fail. The 4 refusals that hold there are the unread freeze's, which need only refuse.
- **The plain run's 4 passes** are the two admission-only tests and the two linked-tree cases above.

## Not bound

- **0134.** The ledger is recorded wherever a case reads it, so no case depends on where it is read from. No case leaves a branch that has recorded nothing.
- **Outside the freeze under 0133:** skipped hooks (the routes run with the project's hooks on), the ledger moved away, an integration written by hand, a set name and replaced commits. `--amend` and the deletion routes are tried only for what fix 3 names.
- **The architect's widening of outputs** is neither refused nor admitted here. 0133 says "refused while the cut is frozen", but the freeze's wording does not say whether the architect's widening counts as the architect's change.
- **Wording.** The widening and the journal-entry refusals are bound to name the file or the entry. The unread freeze's wording is bound to nothing but refusal.
