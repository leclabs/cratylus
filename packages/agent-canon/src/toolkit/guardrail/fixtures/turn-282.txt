You were right to push, though not for the reason my report implied — and my report is what misled you.

**The premise was mine, not the code's.** `packageManager` appears exactly once, in the root `package.json`. Never per-package, and a per-package one would be ignored anyway. The other two `package.json` files in that commit were biome format drift — `"files": ["dist"]` collapsed onto one line — in a separate commit. I listed three files of the same basename without saying they were there for two different reasons, so you audited a thing that never happened. My fault.

**But the smell was real, and it was in the other file.** The actual defect: `mise.toml` said `pnpm = "11"` while `packageManager` said `pnpm@10.0.0`, and *every command ran 10*. The bump sat inert because two files disagreed and only one of them is read.

My reflex was a gate asserting the two versions match. That's the mechanism-flight I have a standing note about — a gate policing a redundancy I could just delete. So I did the semantic question first: **do these two fields assert the same proposition?**

They don't.

- `packageManager` answers *"which pnpm is this repo built with."* It's authoritative — pnpm self-switches to it, and corepack honors it exactly. I proved that: a directory pinned to `pnpm@10.15.0` makes `corepack pnpm --version` report `10.15.0`. It beats whatever mise puts on PATH.
- `mise.toml` answers *"is a pnpm present to bootstrap with."* That's a provisioning fact it can enforce. A **version** there is a claim it cannot.

So writing `11` in `mise.toml` wasn't redundancy — it was a file asserting something it has no power to make true. Changed it to `pnpm = "latest"`, matching the `uv` idiom already in that file. The version fact now has one home; disagreement is structurally impossible rather than merely policed.

I considered dropping pnpm from `mise.toml` entirely and letting corepack bootstrap. Rejected: corepack isn't enabled on this host, so it'd force `corepack enable` onto every fleet host — and fleet provisioning is explicitly walled off from this repo.

Amended into `b195b1b` (nothing pushed, so no reason to leave "introduce redundancy → remove redundancy" in the history). Full gate green on node 26.5.0 / pnpm 11.17.0.
