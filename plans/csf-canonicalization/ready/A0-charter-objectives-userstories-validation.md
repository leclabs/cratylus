# A0 — Charter: objectives, user stories, blind-validation strategy

**Intent.** The first task after `/wake`. Before any machine work, ground the plan so success is
defined and falsifiable:

1. **Objectives → delivery.** Restate polis's objective in the operator's terms (polis self-extends
   on a layman's behalf; canonical CSF substrate; `elicit → CSF → recompose into domain skills →
agents-as-persons`) and map exactly how each phase of this plan delivers it.
2. **User stories = success criteria.** Write the user-story set for **both** audiences —
   polis-developer / context-engineer, and layman-operator — each as
   "As a <role>, I want <capability>, so that <outcome>," concrete enough to test. These ARE the
   acceptance criteria for the plan.
3. **Blind-validation strategy.** For each story, state how success is proven by blind testing —
   lock-my-answer-first then a fresh `general-purpose` subagent on the identical prompt; the
   canonical-anchor test (blind-signify ≟ filename); round-trip + reconstruct equivalence. Map each
   criterion to its blind test.

**Acceptance.** A charter doc in the plan carrying all three, **reviewed and agreed by the operator**
before Phase A execution proceeds. No machine work starts until the success criteria are locked.
