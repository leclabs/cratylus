## Constraints (design decisions)

0. **Import-flip (S1 recon).** Anatomy skill cells currently type against a LOCAL reimpl
   (`../toolkit/skill-cell.js` — `SkillCell`, `SkillExpression`). **Switch each cell's type import to
   agent-forge's `Skill` + `SkillExpression`** (`@leclabs/agent-forge/anatomy`). Do NOT patch the local
   `toolkit/skill-cell.ts` — it is deleted in S5; flip AWAY from it. The **12 `TS1117` dup-key errors** (the
   Operator's partial `body→formalBlock` find-replace) resolve by ADOPTING forge's shape, not by renaming
   around them. **Forge's dist is already freshly built (S1 landed) — do NOT rebuild agent-forge** (a concurrent
   sibling shard is running; a rebuild would race its dist). Type against the current dist as-is.
1. **NO stored `body`.** Each skill cell = `{ name, description, formalBlock, composition }`. Author the σ\*
   payload as `formalBlock: <expr> as SkillExpression` (inline, or as a named `const …Notation: SkillExpression`
   per the carry-on pattern — authoring style is your discretion). **Delete every `body:` markdown field.** The
   SKILL.md is generated by the adapter (S3), never stored here.
2. **`description` is σ_human\*** — a human-facing selection-line in prose ("use this skill to …"). Do NOT
   residue-tighten it, do NOT make it σ*. If a cell's current `description` is a σ* fragment, rewrite it to the
   σ_human\* selection line (mirror carry-on's `description`).
3. **`formalBlock` is σ\*** — the self-sufficient set-builder block, declarations-above / laws-below, R=LLM
   density. It must be the SAME operative content the old `body`'s fenced block carried (no semantic loss).
4. **Agents get a σ_human\* `description`** — add the "Use this agent when …" selection line (the form the
   harness roster's well-formed agents carry). Keep `persona` unchanged (it stays σ*). nico/mav currently leak
   the persona as description — give them a real σ_human* description.
5. Fix ALL `TS1117` dup-property errors in `skills/*` by adopting shape (1), not by renaming around them.
