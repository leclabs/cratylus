# T6.2 — Rehome build-provenance out of the injected SOUL body

**Phase** 6 (cleanup) · **Lane** Nico (design) + Mav (projection) · **Depends on** T6.1 (do it AFTER the
byte-identical cutover proves fidelity) · **Gates** nothing.

## Finding

The deployed SOUL injects the `<!-- GENERATED … -->` provenance comment — **source-path, profile, and
content-hash** — into every agent's context (only YAML frontmatter is stripped; the comment sits after it,
in the body). Confirmed against live SOULs. This is build/drift machinery metadata the _running agent_
never consumes — **the same class of build-meta leak as the `packages/mind/<organ>` preamble we deleted
in `826a9f0`.** The preamble deletion was step 1; this is step 2 of the same principle (build-time
internal facts don't belong in an agent's identity/context).

## Scope

Separate the two purposes the comment conflates and move both out of the injected body:

1. The **"generated, don't hand-edit"** note — for a _human_ editing the file, useless to the running
   agent. Keep it where a human-editor sees it but the LLM doesn't (frontmatter or a top-of-file form the
   harness strips), or drop it (the file is regenerated regardless).
2. The **content-hash / source-path / profile** — for `deploy.py`'s drift read-back. Move into frontmatter
   (harness-stripped from context, still in the file so the drift grep still finds it) or a sidecar.

Net acceptance: **zero build-meta in agent context**; the drift machinery still reads the hash from its new
home (verify the read path).

## Sequencing caveat (load-bearing)

This is an **intentional divergence** from the Python byte-identical baseline (the current projection
faithfully reproduces the comment). Do it as a deliberate, isolated step **after** the cutover (T6.1) has
proven byte-identical fidelity — do NOT fold it into the T2.1 projection or it muddies the migration's
acceptance invariant. Once landed, the new baseline is "byte-identical except the rehomed provenance."

## Acceptance criteria

- No `<!-- GENERATED -->` / content-hash text in any deployed agent's injected context (check a live SOUL).
- `deploy.py` (or its koine successor) drift read-back still resolves the content-hash from its new home.
- Whether the harness strips unknown frontmatter keys from context is **verified**, not assumed.

## Out of scope

The byte-identical migration itself (T1–T2, T6.1).
