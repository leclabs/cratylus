# T6.3 — migrate the toolkit hooks onto koine machinery

**Concern** hooks as koine config · **Lane** Mav (koine engine/adapter/deploy) + Nico (design calls, re-verify) · **Depends on** T6.1 · **Gates** plan retirement (the last toolkit capability)

## Goal

The Python projector/deployer is gone (T6.1); the only capability still living as hand-rolled
`toolkit/` shell is the **two hooks**. The Operator's directive: **all old toolkit capability,
including hooks, must run on koine machinery.** End-state: no agent-hook is installed by bespoke
`git config` + `jq` shell; koine **projects + deploys** them. Ideally `toolkit/` disappears.

## What exists

- koine **already projects Claude hooks**: `Hook` IR resource (`src/core/ir`, `events` →
  canonical), and the **claude adapter** serializes `ir.hooks` into `.claude/settings.json`
  (`{type:'command', command, timeout}` under Stop/SubagentStop/PreToolUse/…). `src/adapters/claude/write.ts`.
- koine has **no git-hook handling** (its Hook IR = Claude settings.json hooks only).
- Current toolkit hooks:
  1. **stance guardrail** — a **Stop + SubagentStop** Claude hook; `stance-guard-toggle.sh` hand-edits
     `.claude/settings.local.json` via `jq`; worker = `guardrail/stance-guardrail.sh` (+ judge + rubric).
  2. **continuity nudge** — a **git `post-commit`** hook (`.husky/post-commit` → `continuity/praxis-advance-nudge.sh`);
     reminds on plan-mirror drift. Opt-in `git config polis.continuity`.
