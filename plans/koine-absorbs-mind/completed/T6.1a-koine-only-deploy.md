# T6.1a — koine is the only deploy path

**Concern** deploy machinery · **Lane** Mav (engine) · **Depends on** — (ready) · **Gates** T6.1e, T6.1g

## Context

`koine deploy` (src/deploy/ + cli/commands/deploy.ts) is built, committed, and **parity-proven**
byte-identical vs Python `place/local.py` (179 deploy tests, `parity.test.ts`). But the live fleet
deploy still calls `uv run … python toolkit/deploy.py`. This task makes koine the **sole, documented,
runnable** deploy path so the Python deployer can be deleted (T6.1e) and the fleet redeployed (T6.1g).

## Work

1. Confirm `pnpm build` emits the `koine` bin (`packages/koine` → `dist/cli/index.js`, `bin.koine`).
2. Add a runnable convenience entry so an operator deploys without remembering flags — a root or mind
   `package.json` script (e.g. `mind:deploy` / `mind:project`) that runs `koine project` (→ render tree)
   then `koine deploy --kind agent && --kind skill`. Projection today = `pnpm --filter @leclabs/mind project`
   (tsx project-cli → koine claude adapter); wire deploy to consume that render tree.
3. **Dry-run proof, local:** `koine deploy --dry-run --kind agent --scope user` and `--kind skill` against
   the freshly projected tree; show it would place all 11 agents + 16 skills (incl. memory bundle).
4. Document the koine deploy command (incl. `--host/--user/--fleet/--only/--exclude`, seed-if-absent,
   bundle hard-error) where `toolkit/AGENTS.md` currently documents `deploy.py` — the new canonical runbook.

## Acceptance (blind-testable)

- A single documented command projects + deploys the whole corpus via koine, fleet-aware, no Python.
- `koine deploy --dry-run` enumerates all agents+skills byte-identical to what `deploy.py` would place
  (parity.test.ts already green is the oracle; cite it).
- `pnpm build/test/lint/typecheck` green.

## Out of scope

The actual fleet redeploy (T6.1g); deleting `deploy.py` (T6.1e).
