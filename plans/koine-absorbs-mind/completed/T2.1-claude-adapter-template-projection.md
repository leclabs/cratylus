# T2.1 — Project mind through the claude adapter via template literals

**Phase** 2 (adapters as projection) · **Lane** Mav · **Depends on** T0.1, T1.2, T1.3 · **Gates** T2.2, T2.3, T6.1.

## Reframe

"Project mind to Claude Code" = **export the typed Agent/Skill through koine's claude adapter.** There is no separate mind renderer. Upgrade the claude adapter's serializer to project a mind `Agent`/`Skill` by composing fragments with template literals (today it uses gray-matter; the upgrade is expressive template-literal projection).

## Scope

1. In koine's **claude adapter** `write`/serialize: render `Agent` → `.claude/agents/<name>.md` and `Skill` → `skills/<name>/SKILL.md` via template literals over the typed object (frontmatter from derivations: persona→description, provenance→{emoji,hue}→color; `## <Organ>` sections from the organ fields).
2. Provenance header + content-hash (over body substance) as a shared projection helper.
3. The skill-dir / verbatim `## Tool` projection for `memory`.

## Acceptance criteria

- The claude adapter projects the whole corpus **byte-identical** to the current `.claude/{agents,skills}` artifacts (self-application gate) — no Python toolkit involved.
- `pnpm build/test/lint` green; the legacy `mind.koine.json` parity test either passes or is superseded by this direct projection (note which).
