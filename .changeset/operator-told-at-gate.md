Attach on omp tells the operator. A delegate holding a gate may have ended its turn there by any route: its dispatched run, judged as that run ends rather than when the dispatch's other blocking items settle; a later run that the operator, a dispatcher's message or a peer's message started; or a background delivery. However it got there, and however deep the holder sits below other delegates, the operator's own session shows a warning line naming the agent and how to join it in omp's Agent Hub (Alt+A, select the agent, Enter). The notice is omp's `notify`, which no model reads, and is given once per gate.

A sign-off holder's turn now holds a gate only when its reply ends with the sign-off it waits on, a current request to the operator. Its closing sentence, read across line breaks, is either a bidding starting "(Please) sign off …" or a question asking the operator to give it ("Do/Will/Would/Can/Could you sign off …?", "… your sign-off?"), whatever else it says, or a present wait on the operator's sign-off ("waiting on/for your sign-off", "awaiting your sign-off", "pending your sign-off") that the words governing it neither negate nor put in the past. Any other question, and a bare report, holds nothing. Every other reply reaches the dispatching session unchanged as its result, whether or not it is the declared JSON deliverable. This applies to holders that declare no JSON deliverable too, so the architect no longer holds a gate at every turn it ends. Each gate is told once, by the run it ends, and a background delivery is tied to the run it came from, so a late report of an earlier run is never told twice nor silences a later gate.
