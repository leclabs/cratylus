`omp --agent <name>` starts the main session as any agent declaration omp discovers (decision 0047), through cratylus's one omp extension, `~/.omp/agent/extensions/cratylus.ts`, which `cratylus install --harness omp` places. The extension registers the `agent` flag and resolves the name with omp's own agent discovery, the declarations omp's `task` dispatch runs (`.omp/agents/` nearest the session's directory, then `~/.omp/agent/agents/`, then extension packages, plugins and bundled agents such as `scout`), read afresh for each new session. The session runs on the model and thinking level omp's dispatch would run the declaration on, resolved by omp's own resolver: a role alias is expanded, and a level a model selector carries (`provider/model:high`, directly or in a role's configured value) wins over `thinking-level`. An explicit `--model` or `--thinking` on the command line wins over the declaration's, each for its own part. Every turn's system prompt carries the declaration, its name and description as a sentence and then its body, never its raw front matter; and the status line shows the declaration's `mark` and name, or the name alone (a bundled declaration has no mark). The extension never changes the active tools: `omp --agent <name> --tools …` holds exactly what plain `omp --tools …` holds, and a declaration's `tools` are for dispatch only. An unknown name ends startup with a non-zero exit naming it, before any session starts. Without `--agent`, and in subagent sessions, the extension adds nothing. Its capability tools are unchanged.

Wherever install places that extension on omp it also lists omp's `status` segment in the host's status line (or shows the hidden status row again), whether or not the corpus delivers any agent, so the name and mark render on a host that had hidden extension status.
