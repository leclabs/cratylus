The turn-end stance guard no longer locks a session in an endless loop over one stop. The turn end is the one exception to a refused act staying refused: refusing it holds back no effect, it only makes the agent redo its turn. Every turn is still judged; only what follows a BLOCK changes. A stop that follows a block of the guard (`stop_hook_active`) continues a run of blocks, and a stop that follows none starts a new run at 0. When the judge's BLOCK survives the evidence checks and the run already holds a block and this turn is byte-identical to the turn last blocked in it, or the run already holds 3 blocks, the stop is let through and the guard says so on both harnesses (`STANCE GUARDRAIL`, the stop let through UNRESOLVED, the finding standing, the judge's reason). A run that cannot be counted (its record unreadable, or the state dir unwritable) lets a following stop through the same way, and a fresh stop there still blocks. The bound is on one stop, never on the session, and the 3 is a constant in the cell that no environment variable sets. The reason the agent reads keeps a count but no longer claims the gate never stops enforcing.
