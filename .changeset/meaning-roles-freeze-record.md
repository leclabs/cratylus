The runtime holds what is frozen. A cut is frozen from its `workPackage open` until its new `workPackage integrate`. From its opening, for each of its contexts, it freezes its examples, its held-out example text `design/judgment/<context>/<cut>.md` and each concept its examples name, in its own context. The new `workPackage freeze --cut <cut> --check <path>` (a file, or a folder ending in `/`) freezes the checks it names, a held-out check under `design/judgment/<context>/<cut>/` only once a freeze names it: the judgment folder is never frozen by implication (decision 0125), so a check-writer can write held-out checks after the cut's other checks are frozen. `workPackage frozen` answers every cut opened and not integrated, with its architects, examples, checks and concepts, and also `uses`: the files its frozen checks' relative imports reach, transitively, that no work package of the cut outputs; and `unchecked`: its visible examples, as `<context>/<n>`, that no file under a frozen check names. It is the one account of what is frozen, exported in process as `frozenCuts`.

The agent making a capability call is named in `CRATYLUS_AGENT` (`ACTING_AGENT_ENV`, `actingAgent`); absent or empty it is unknown and never an architect. `integrate` is refused unless that agent is the architect the cut records for each of its contexts; it ends that cut's freeze only, keeping its history, and another cut not integrated still freezes what the two share. `concepts supersede` and `concepts retire` of a frozen concept are refused in one line, before anything is appended, naming the concept, the cuts and their architect, unless the agent is the architect of every cut freezing it; the same name in another context is untouched. `workPackage state` tells whether the cut is integrated.

The freeze holds at the record (decisions 0128, 0129). A hidden, harness-facing `cratylus freeze-gate`, never a capability verb nor an agent tool, runs as git's `reference-transaction` hook: in the `prepared` state it refuses any branch update that brings in a change to a frozen example, held-out example text, frozen check, file a frozen check uses, or a journal entry superseding or retiring a concept a cut not integrated realizes, unless `CRATYLUS_AGENT` names that cut's architect. The refusal names the branch, the cut, its architect and the paths, and the branch stays where it was. Every route that moves a branch meets it, `--no-verify`, amends, merges, cherry-picks, rebases and `update-ref` included. When the ledger is present and what is frozen cannot be read, every branch update and every journal `supersede` and `retire` is refused, saying why; other states, other refs and a repository with no ledger pass silently. The freeze holds against agents under the name the harness gives them and wherever the project's hooks run: a name set by hand, or hooks switched off, is outside it (decisions 0130, 0131). This repository wires it through `.husky/reference-transaction`, and `prepare` adds the hook entry husky's list lacks.

What is frozen is read from the record (decisions 0132 to 0134): a cut's examples and the concepts they name, its checks and the files they use as the branch's recorded tip holds them (`HEAD` for `workPackage frozen`, the journal and the dispatch rule; the tip before the update for `freeze-gate`), never as a working copy has changed them, and from the working copy only what the tip does not hold or a branch with no commit yet. The ledger is read where cratylus keeps it, in the work tree the call or update is made in, or on a push the repository's own. `workPackage submit` and `update` refuse, while the cut is frozen, to widen a package's outputs onto a file a frozen check uses, naming it; a file a frozen check imports itself from outside its own folder is the work it checks and stays a possible output. `concepts define` of a concept a frozen cut's examples name is refused unless its architect makes it, and every `define`, `supersede` and `retire` is refused while what is frozen cannot be read. `freeze-gate` refuses any branch update that changes or deletes an existing journal entry, from anyone, the architect included, naming the entry; appending stays admitted. It reads the repository from wherever git runs it, so wired in the common hooks folder it holds in every work tree and on pushes into the repository, and it refuses where it cannot read. This repository's `prepare` names its husky hooks folder absolutely, and its hook runs the gate from the checkout's source without `pnpm`, so it reaches linked work trees and pushes too.
