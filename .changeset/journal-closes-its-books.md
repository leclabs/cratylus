The concept journal closes its books. `cratylus concepts close`, and the concept journal tool built from the capability's explanation, appends one entry of kind `close` naming the commit at HEAD that holds the closed period, bringing forward verbatim the entries that stand (the current purpose, each context's current descriptions, each concept's current versions, a retirement included, and each standing decision with its acceptances and governing classification), naming every other entry the period held as closed, recording every id each context has held and each concept's first version, which keep ownership of a delivered context and the readings' order, and how each reference by a decision's name alone bound; it then removes every other entry file, which git keeps at that commit. Every reading folds the brought-forward entries with the period's own and never reads an entry a close named closed, so `state`, `design` and `decisions` answer the same after a close as before, and after joining lines of work that closed or appended separately; the history readings cover the journal since its latest close and carry `booksClosed`, naming it and its commit. A close refuses, changing nothing, outside git or with no commit, while the journal differs from HEAD (an ignored file included), while it reads past entries of a newer runtime, with no entry, or with nothing recorded since the latest close; where a file cannot be removed it restores the journal from HEAD and removes the close. A verb's explained `effect` is now `reads`, `appends` or `closes`; the omp tool asks for write approval for a verb that closes.
