`omp --agent <name>` now starts the main session with the whole declaration, as omp's `task` dispatch gives it to a child, resolved by omp's own resolvers. Every turn's prompt carries, after the declaration's text, the full instructions of each skill its `autoload-skills` names that omp discovers for the session, in omp's autoload form (an unknown name is skipped). The session runs without omp's default personality; with summarised reads on or off as `read-summarize` says (unsaid, the session's own setting); with the advisor and the pre-planning hand-off (prewalk) the declaration names, `task.agentAdvisor` and `task.agentPrewalk` entries first, and neither when it names none (a hand-off the configuration armed is dropped first, so a declared target wins). It dispatches only the agents its `spawns` names (`*` any; absent, as omp reads it: `*` with `task` among the `tools`, else none; an explicitly empty `spawns`, an empty list or a blank string, none even with `task`), omp refusing any other with `Cannot spawn '<name>'. Allowed: …` through `before_subagent_spawn`; its children's own dispatch is untouched. Two values omp's own dispatch does not hold are held by launch as the declaration says: an explicitly empty `spawns` with `task` among the `tools` (omp's discovery reads it as `*`), and `read-summarize: true` (omp's dispatch applies only `false`); every other value is held as omp's dispatch gives it to a child. These settings are session-scoped runtime overrides, never persisted, applied once per launch and put back when the launch ends. The operator's `--model`, `--thinking`, `--advisor`, `--prewalk`, `--no-prewalk` and `--prewalk-into` win their own part; the tools are never touched, so without `task` the session cannot dispatch. A session without `--agent`, and every subagent session, are unchanged.
