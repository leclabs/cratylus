The omp extension names the acting agent on every capability call, in `CRATYLUS_AGENT`: the declaration a main session was launched as, the agent a dispatched session runs as, and no one otherwise. It drops any value the environment carries in, so no shell command inherits one. A capability's refusal is now returned as a tool error (`isError: true`) carrying the command's own message, never thrown.

The extension gates what is frozen, in every session, before a call takes effect. A `write`, `edit` or `ast_edit` of a path a frozen cut freezes (its examples, judgment and judgment folder, and its frozen checks, as `cratylus workPackage frozen` answers) is refused, naming the cut and its architect, unless the acting agent is that cut's architect. A `bash` or `eval` call that names a frozen path, or names `CRATYLUS_AGENT`, is refused the same way. Outside a repository nothing is frozen. When what is frozen cannot be read, the call goes through and the session is warned.

The gate reads every route omp offers to change a file, whether called as a tool or through its `xd://` device. `ast_edit` is refused at staging, before `resolve` applies it, when its `paths` name a frozen file, a folder holding one, or a glob matching one. `lsp` `rename`, `rename_file` and `code_actions` with `apply` are refused on the files they name. `edit` is refused on the files every patch form names: hashline headers with or without a tag, `MV`, `apply_patch` and sloppy headers, and a `patch` entry's `rename`. `write` is refused on a frozen path that is hashline-wrapped, `file://`, or behind an archive or database selector. A `conflict://` write is refused while a frozen file holds a merge conflict. `tts` is refused on its output, and `security_scan` on its output root. Calls to `debug`, `ida`, `computer`, `vibe_spawn` and `vibe_send`, and raw `lsp` requests, are refused like a program when they name a frozen path, and a `bash` call is read from its own `cwd` too. A call that only reads is never refused.
